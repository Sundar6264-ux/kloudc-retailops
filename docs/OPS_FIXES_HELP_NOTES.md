# Help notes from the Sep 29 ops fixes (for batch 3)


## A

- Fix Issues (web Reports > Fix Issues, app Fix Issues) has five more lists, each with the same Close-with-reason / Closed list / Closed report / bulk close / details / CSV as the barcode lists. Street Kitchen and Catering Menu items are left out, as before. Every list reads the latest inventory upload.
- Negative inventory (moved here from Reports): on hand below zero in the latest upload. Reasons: Count corrected in Toast (re-checked: comes back if the next upload still shows it), Sold before the delivery was received in Toast, Rung up under the wrong item, Loose / weighed item, Item discontinued.
- Refill from container: the shelf (priced) row shows 5 or less while the item's Container-location row (same name, no price, no vendor) has more than 0. Shows Store qty and Container qty side by side. Items whose name has two priced rows are skipped (different products). "Moved stock to the shelf" is re-checked against the next upload.
- Slow moving - Review: the Supplier Projection forecast (availability-adjusted, its default 3-month window) classes the item Slow AND shows the red Review tag - i.e. one of: not enough history, long stockout, sales spike capped, unusual trend, negative on-hand, very different from the simple average. "Why review" shows which.
- Dead with stock: that same forecast classes the item Dead (no sale in 60 days while in stock) and on hand (shelf + container) is above 0. It uses our own sales data and knows the days an item was out of stock.
- (Follow-up, owner's call) "Dead inventory" (the older list from Toast's own 90-day sales figure, which also included "Slow" = 90+ days of stock) is no longer shown on the website or in new app builds - Dead with stock replaces it. The app's Inventory Reports "Dead Stock" tile and a search for "dead stock" / "dead inventory" now open Dead with stock. Help pages still describe "Dead inventory" (web HelpPage "Dead inventory" section, the Inventory Reports / Fix Issues intros, app help content) - replace with Dead with stock. Older closures of Dead inventory still show in the Closed report.
- Dead - newly arrived: brand-new products only - an item that has never sold, arrived 5 to 30 days before the latest upload, with stock on hand. A restock of something that has sold before is never listed here, even if it hasn't sold since the delivery (owner's call). Arrival = the later of Toast's "last received" date and the day the item first showed up in the uploads. After 30 days it drops off this list and is treated as ordinary stock (a new item still unsold by then is normally already in Dead with stock, which needs about 4 weeks in stock with no sale).
- (Verifier A) Negative inventory and Refill from container are conditions that come and go, so a close (other than "Not an issue", and for negative "Loose / weighed" / "Item discontinued") covers that occurrence only: once a later upload shows the count back at 0+ / the shelf above 5, the item returns to the open list if it happens again. "Sold (30 days)" on these lists is units sold (Toast's "last 30 day orders"); the details panel's Sales lines show units and dollars, e.g. "14 sold ($62.16)".
- (Verifier A) The Slow / Dead forecast is worked out in the background after every inventory upload, shortly after a server restart and after the nightly sales sync, so the page opens in well under a second.

## B

- Margin report removed everywhere (web Inventory Reports, app Inventory Reports, Ask Inventory Bot tool, Weekly Digest data). Negative inventory is no longer in the Reports hubs - it lives in Fix Issues now. Help pages still describe the margin report (web HelpPage "Margin report" section + Ask/Digest mentions, app help_content "Margin report" + Ask text) - remove those.
- Every report is now downloadable as CSV. App (More > Reports): download icon (top right) on Items Sold, Open Orders (today or all-time, whole list), Vendor Price Comparison, Price Change Log, Reconciliation Report / Demo (demo gives every item in its window), Invoices Without a Logged Purchase, and Log a Purchase (the purchase log) - it opens the CSV preview with Share/Save, same as Fix Issues. Web Inventory Reports: the sales export, price change log and vendor price comparison were already downloadable.

## C

- Placed Orders: a full history of purchase orders, newest first. Web: Ordering > Placed Orders (also "See all placed orders" on the Purchase Order Cart); filters for vendor, date range (store time), status and a search on item name/code/vendor; click an order to see its items. App: Ordering tab > Placed Orders, the cart's receipt icon, or Home's Recent Orders Placed "View all"; grouped by Today / Yesterday / date, vendor chips, search, status filter (tune button), pull to refresh, more load as you scroll. Same access as the Purchase Order Cart.
- Status: "Placed" = someone pressed Mark placed (app) / Order placed (web), recording what was in that vendor's cart. "PDF only" = a PO PDF was made (downloaded, or opened in the app to share on WhatsApp) but never marked placed. Making the PDF again within 24h updates the same entry, and Mark placed within 48h turns it into the Placed order - so a preview plus Mark placed is one order, not two. A repeat Mark placed within 2 minutes returns the same order. Home's Recent Orders Placed only shows Placed orders.
- Order again (expand an order): puts that order's items back into the vendor's cart with the same quantities (an item already in the cart gets the order's quantity).
- Only Placed orders count as "ordered" elsewhere: a PDF-only entry does not close the "Place the <vendor> order" task, and it isn't the vendor's "Last placed" date on Reorder Candidates. Sending the PDF on WhatsApp still needs Mark placed to count.

## D

- Hide sales numbers (per user): an admin ticks "Hide sales numbers" for a non-admin on the website Users page (Add a user, or the "Sales numbers" column) or in the app's Manage Users (a switch on each user card and in Add user). Admins always see sales, so there's no switch for them.
- What that person no longer sees: Today's / Yesterday's sales tiles on Overview, Items Sold (gone from the menu; opening it says "Sales numbers are hidden for your account"), the sales CSV/PDF download on Inventory Reports, open-order totals (web, app, CSV), the weekly revenue column in an item's weekly breakdown, the Weekly Digest's sales section, and the Ask bot declines sales questions. The server enforces it too (403 or blank totals), so it can't be worked around.
- What stays: everything used for ordering and stock - demand per day/week, reorder and Supplier Projection quantities, units per week in the weekly breakdown, reconciliation, delivery review, Fix Issues "last sold". Unticking the option brings everything back straight away (on the next page load / app refresh).
- Also hidden (verifier): Fix Issues item details show units sold only ("14 sold", no "($62.16)") and no weekly dollar column; the Overview "Sales sync" status keeps its time but not its "N line items from M orders" detail.

## E

- Supplier Projection "Also at": under an item's name, the other vendors Toast lists for that item (its vendor field can hold several, separated by ";"), with each vendor's own item code when Toast has it. Shown on the website row and on the app card and details sheet.
- "Similar" (website: button under the item name, with the count; app: "Similar products" in the item's details sheet): other products in the store of the same kind - other brands and pack sizes of the same product first ("Same product, other brand", "Same product, different size"), then close variants ("Similar type"). E.g. Deep Shredded Coconut -> Daily Delight Grated Coconut, Laxmi Grated Coconut 400g / 1.2kg, Vadilal, KX... Each shows on hand (shelf + container), price, cost, every vendor with its code, and units sold in the last 30 days (our own synced sales, not Toast's dollar figure), with Add to cart (to its vendor; pick one when it has several; with no vendor on file it goes to the vendor you're projecting). Street Kitchen / Catering items and Container rows are never listed.
- How it's matched (no internet or AI at run time): the name is cleaned up - pack size ("24oz", "2 lb", "20pcs") and brand ("Deep", "LX." = Laxmi, "DD" = Daily Delight...) are taken off, spellings and Indian names are made the same (toor/tuvar/arhar, jeera/cumin, rava/sooji/semolina, besan/gram flour, grated/shredded coconut...), and what's left is compared. Rarer words count more; a different department, frozen vs shelf, or a clash like coconut MILK vs GRATED coconut or powder vs whole lowers the match. The word lists live in backend/app/data/similar_products/ and the matcher is rebuilt after every inventory upload.
- Accuracy (hand-checked on 101 real items): about 9 in 10 of the first five suggestions are right. It can miss a match whose name shares no product word with the item (a brand-only name like "Nescafe Gold" is only found for coffee because Nescafe is on the list of brands that mean one product), and it can't fix a product Toast has filed in the wrong category.

## G

- Definitions everywhere: every status / tag / label (Critical, Order now, Check count, Review, Regular / Intermittent / Slow / Dead, Placed / PDF only, invoice statuses, calendar statuses, Fix Issues lists, Variance...) has a small (i) next to it on the website; click it for a short definition and "How it's worked out" with the real numbers. In the app, tap the chip itself (or long-press / the small (i) where the chip already has its own tap).
- Glossary: all definitions in one place, grouped and searchable - website sidebar "Glossary" (/glossary, everyone), app More > Glossary (Home search finds "glossary", "definitions", "what does critical mean"). "All definitions" in any popover opens it at that term.
- One source: backend/app/glossary.py (served at GET /api/glossary). The rule texts are built from the code's own thresholds, so they change when the rules change. The app ships a copy so it works offline and refreshes it from the server. Help pages can link to /glossary instead of repeating the definitions.
